# WebSocket API Documentation

Этот сервер автоматически генерирует документацию для всех WebSocket событий.

## Доступные эндпоинты

- **WebSocket UI**: `http://localhost:3000/docs` - Красивый кастомный интерфейс для WebSocket документации
- **Swagger UI**: `http://localhost:3000/docs/swagger` - Стандартный Swagger интерфейс
- **JSON документация**: `http://localhost:3000/api/docs` - Документация в JSON формате
- **OpenAPI спецификация**: `http://localhost:3000/api/docs/openapi` - OpenAPI 3.0 спецификация

## Автоматическое обновление

Документация автоматически обновляется при:
1. Добавлении новых событий в `user-socket-events.ts` или `game-socket-events.ts`
2. Изменении структуры существующих событий
3. Добавлении новых категорий событий
4. Изменении типов данных в `types/` директории

## Структура событий

### Пользовательские события (Users)
- `user:connect` - Подключение пользователя
- `user:disconnect` - Отключение пользователя
- `user:get` - Получение информации о пользователе
- `user:update` - Обновление информации о пользователе

### Игровые события (Games)
- `game:create` - Создание новой игры
- `game:start` - Начало игры
- `game:join` - Присоединение к игре
- `game:get` - Получение информации об игре
- `game:word` - Отправка слова в игре

## Добавление новых событий

1. Добавьте событие в соответствующий файл событий
2. Документация автоматически обновится при следующем запуске сервера
3. Для более детального описания используйте `DocumentationService.registerEvent()`

## Пример использования

```typescript
// Автоматическое извлечение
docService.extractFromSocketEvents(myEvents, 'MyCategory');

// Ручное добавление метаданных
docService.registerEvent('my:event', {
  description: 'My custom event',
  parameters: [
    { name: 'param1', type: 'string', description: 'Parameter description' }
  ],
  category: 'MyCategory',
  direction: 'incoming'
});
```

## Детальные примеры

Все события содержат корректные примеры данных:

### Пользовательские события
- **user:connect**: Принимает имя пользователя, возвращает объект пользователя с ID
- **user:disconnect**: Принимает ID пользователя, возвращает подтверждение отключения
- **user:get**: Принимает ID пользователя, возвращает информацию о пользователе
- **user:update**: Принимает объект пользователя, возвращает обновленную информацию

### Игровые события
- **game:create**: Принимает ID игрока, возвращает созданную игру
- **game:start**: Принимает ID игры и начальное слово, возвращает начатую игру
- **game:join**: Принимает ID игры и ID игрока, возвращает подтверждение присоединения
- **game:get**: Принимает ID игры, возвращает информацию об игре
- **game:word**: Принимает ID игры, ID игрока и слово, возвращает отправленное слово

## Типы данных

Документация включает полные схемы для всех типов данных:

- **User**: Пользователь с ID и именем
- **Game**: Игра с раундами, игроками и состоянием
- **Word**: Слово с информацией об игроке и времени
- **Round**: Раунд с коллекцией слов
- **Error**: Ошибка с сообщением и кодом

## Особенности

- **Автоматическое извлечение**: Документация извлекается автоматически из кода событий
- **Корректные примеры**: Все события содержат реалистичные примеры данных
- **Категоризация**: События группируются по категориям (Users, Games)
- **Направление**: Различаются входящие и исходящие события
- **Обработка ошибок**: Документированы все возможные ошибки
- **OpenAPI совместимость**: Генерируется стандартная OpenAPI 3.0 спецификация
